= Visão Geral das Subscrições Red Hat

Três fatores desempenham um papel importante na seleção da subscrição RHEL correta:

* O SLA (Service Level Agreement)
* O número de _sockets_ (físicos) e,
* O número de máquinas virtuais.

Red Hat Enterprise Linux can have layered products, like clustering. These require a separate subscription.

== _Service Level Agreement_
Uma parte importante de uma assinatura é o acesso ao suporte da Red Hat. O SLA associado a uma subscrição desempenha um papel importante para o cliente, pois define os tempos de resposta.

== Sockets físicos
Uma convenção das subscrições de RHEL é baseada em pares de _sockets_. Um _socket_ aqui é o _socket_ físico da CPU.

Qualquer subconjunto de um ou dois _sockets_ conta para um par; portanto, um servidor com 16 _cores_ e dois _sockets_ requer uma subscrição para estar comercialmente em _compliance_. Um servidor com quatro _sockets_ exige duas subscrições de pares de _sockets_ para estar em _compliance_.

Um servidor com apenas um _socket_ exigirá uma subscrição para estar em _compliance_ e um servidor com três _sockets_ exigirá duas subscrições.

Obviamente, uma regra excepcional da-se quando um nó que tem quatro _sockets_ físicos, dos quais apenas dois têm uma CPU instalada, exigindo, portanto, apenas uma subscrição para estar em _compliance_.

== Virtualização
Como alternativa, uma subscrição RHEL convencional pode ser usada para registrar máquinas virtuais RHEL. O número de máquinas virtuais incluídas em uma subscrição é de dois.

Uma subscrição que se aplicaria a uma máquina de _socket_ duplo físico também pode ser usada para duas máquinas virtuais. O número de _sockets_ virtuais ou vCPUs atribuídos às duas Máquinas Virtuais utilizadas por uma assinatura RHEL convencional não é relevante.

=== Subscrições de Virtual Datacenter 
As subscrições do Virtual Datacenter (VDC) diferem das assinaturas RHEL convencionais, pois registram VMs por hypervisor em vez de individualmente.

As subscrições de VDC usam um relacionamento pai-filho para validar a subscrição de uma VM: o pai (o _hypervisor_) consome uma subscrição enquanto os filhos (as VMs executadas nesse _hypervisor_ em particular) "utilizam" essa assinatura. Quaisquer VMs RHEL suportadas em execução em um _hypervisor_ com uma subscrição VDC válida têm uma assinatura válida.

Semelhante às subscrições convencionais, as subscrições VDC são aplicadas aos _hypervisors_ por par de _socket_. Consulte <<Sockets físicos>>.


[NOTE]
====
Uma assinatura VDC é válida apenas para as máquinas virtuais em execução em um hypervisor, não para o próprio hypervisor (o hypervisor deve ter uma assinatura separada para seu próprio sistema operacional).
====

== Produtos em camadas (_Layered products_)
Os produtos em camadas exigem o mesmo SLA e número de pares de _sockets_ que o Sistema Operacional RHEL no qual esses produtos são implantados.

== Ciclo de vida do Red Hat Enterprise Linux
.fases do ciclo de vida
image::subscriptions/lifecycle_phases.png[pdfwidth=80%]
O ciclo de vida tem diferentes fases com diferentes tipos de suporte. Dependendo dos aplicativos, a implantação de servidores pode estar alinhada com as diferentes fases - o modelo ideal é implementar os servidores na fase de "Full Suport", manter na fase "Maintenance Support 1" e substituí-los quando estiver na fase de "Maintenance Support 2".
